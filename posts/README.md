# posts — посты для канала

Папка содержит готовые посты для канала и утилиту для их переноса в редактор кабинета.

## Файлы

| Файл | Что это |
| --- | --- |
| `2026-08-02-dropweb-proxy-launch.md` | анонс браузерного расширения dropweb proxy. Внутри два варианта разметки: rich и запасной обычный HTML, плюс плейн-превью и заметки. |
| `richcopy.html` | утилита: кладёт HTML в буфер обмена с флейвором `text/html`. Один файл, без зависимостей, работает офлайн. |

## Как публиковать

1. Открыть `richcopy.html` двойным кликом.
2. Нажать «Загрузить пост dropweb proxy» либо вставить свой HTML в поле.
3. Нажать «Скопировать как HTML» или Cmd+Enter.
4. В кабинете `cab.dropweb.org` → админка → посты в канал: включить тумблер «Rich-пост».
5. В поле редактора Cmd+A, Delete, затем Cmd+V.
6. Проверить предпросмотр и отправить.

## Главная ловушка

Редактор кабинета построен на TipTap (WYSIWYG) и парсит исключительно флейвор `text/html` из буфера обмена. Копирование HTML-исходника из markdown-файла или редактора кода помещает в буфер только `text/plain`. Из-за этого TipTap вставляет теги как видимый текст. При отправке Telegram возвращает ошибку неподдерживаемых тегов, которую кабинет отображает как «Ошибка HTML-разметки сообщения» (код `invalid_html`). Правило: копировать нужно отрендеренное, а не исходник, `richcopy.html` именно это и делает. При этом сама ошибка ничего не говорит о наличии реальных ошибок в разметке.

## Что теряется при вставке через редактор

При проведении поста через интерфейс редактора некоторые элементы схемы сбрасываются.

- Схема TipTap в `zencab/src/components/admin/content/telegramRichExtensions.ts` не содержит узла `footer`, поэтому подвал сворачивается в обычный абзац.
- Атрибуты `bordered` и `striped` у тега `<table>` не объявлены в схеме, поэтому они отбрасываются.

Если нужен байт-в-байт точный пост, редактор надо обходить через `POST /cabinet/admin/channel-posts` с `rich: true` или `sendRichMessage` бот-токеном.

## Ограничения формата

- rich: до 32000 отрендеренных символов, до 50 медиа-вложений; отдельное медиа-поле запрещено, картинка идёт тегом `<img>` внутри HTML со ссылкой только по https.
- обычный режим: до 4096 символов, с медиа подпись до 1024; из тегов Telegram понимает только `b`, `i`, `u`, `s`, `a`, `code`, `pre`, `blockquote`, `tg-spoiler`, `tg-emoji`; переносы строк выполняются символом новой строки, а не `<br>`.
- `details` допустим только на верхнем уровне документа, внутрь `blockquote`, `li` и `td` его схема не пустит.
- Кастомные эмодзи из пака `dropwebpackv1` рендерятся в канале только у бота с Fragment-юзернеймом; иначе `tg-emoji` деградирует до обычного символа внутри тега, и пост остаётся корректным.
